## 与 v1 的变化

- **删除**：`head_clean`、`hair_front_clean`（v1 重画整脸/前发，导致刘海、脸型漂移）
- **新增**：`head_brow_ready`（只擦除旧头部两小块眉线）、`hair_back_action`（只修补后发内两处旧袖口/手残影）
- **43 张文件重做**：表情、结构拆分、手臂、腿鞋、步态、姿态、侧背/配色
- **37 张与 v1 相同**：粒子、道具、部分表情/结构
- v2 的 `notValidated` 明确列出：运行时动作、大角度遮挡、Photoshop 打开验收

## 组装规则（必须遵守，来自 manifest）

1. **默认显示原母版**，不自动应用任何新增层；`head_brow_ready` 只在换眉时使用
2. 动作换臂使用 `arm_*_up` / `arm_*_shy`（z=65，围裙之后、头和侧发之前），隐藏原手臂；
   配合 `hair_back_action` 替换后发，避免旧袖口/手掌残影
3. 走路用新版无腿 `body`，二选一：独立 `leg_l/r + shoe_l/r`，或一帧 `walk_1..4`；不能两套腿叠加
4. 整图姿态（`sit_pose` / `peek_pose` / `pose_sleep` / `pose_three_quarter` / `pose_back` / `pose_outfit_blue`）
   显示时隐藏所有默认角色层
5. 拆层 z 含小数（如 10.1、49.9、140.1），不要取整
6. 眼/眉/嘴/腮红互斥切换；换眉时必须用 `head_brow_ready`
7. `hand_heart` 仍需前臂绑定配合；`hands_support` 是合层，不是独立上臂动作

## 仍需注意

1. **体积**：parts 13.48MB + 姿态整图，超过当前 DPF 8MB 上限 → 可选包或调整上限/再压缩
2. **动态未验证**：关节旋转接缝、大幅度动作遮挡、走路重心节奏、道具挂点、趴窗台贴边需接入时实机确认
3. **比心**：`hand_heart` 需要运行时把前臂/手切到该层，当前素材本身没有绑定
4. **PSD** 仅结构检查，未在 Photoshop/Krita 打开验收
5. 侧身/背面/蓝色服装是**新视角/新配色生成稿**，不与母版逐像素一致（README 已声明）

## 置顶守卫（2026-11-06）

针对「桌宠层级变低、被窗口遮盖」的反馈。根因不是配置：**窗口的 `WS_EX_TOPMOST` 位本身不是承诺**。别的程序调 `SetWindowPos(HWND_NOTOPMOST)`、shell/DWM 过渡、窗口管理器重排置顶带，都会把她挤到普通窗口下面；而 WPF 只在 `Topmost` 属性**值变化**时才重新置顶，所以一旦被挤下去就一直埋着，直到重启宿主。

复现证据：`SetWindowPos(HWND_NOTOPMOST)` 后 z-index 从 24 掉到 35、`topmost` 位变 0，**持续观察 5s 无任何自愈**。

两层防护（`PetWindow`）：

- **源头否决**：`WndProc` 拦 `WM_WINDOWPOSCHANGING`。`_topmost` 为真时，任何 `hwndInsertAfter != HWND_TOPMOST` 且未带 `SWP_NOZORDER` 的 z 序变更都被改写成 `HWND_TOPMOST`。WPF 自己的移动/缩放都带 `SWP_NOZORDER`，不受影响
- **帧循环兜底**：每 0.5s `EnsureTopmost()`，检查 `WS_EX_TOPMOST` 位 + `HasNonTopmostCover()`（沿 `GW_HWNDPREV` 走，找可见、真实尺寸、且与自身重叠的窗口）。只有**非置顶**窗口遮挡才算被降级，因此不跟任务栏、其他置顶程序抢位

QA 实测：外部降级后 **t+0.2s 掉出 → t+0.5s 自动回到置顶带**；连续 10 次降级 **10/10 全部否决**；放到任务栏下面 2s 后保持不动（不与合法置顶窗口抢）；30s 静置层级稳定。

配套修复 `index.js`：原来只在 `PetHost.exe` **缺失**时才编译，导致已安装用户拿不到宿主修复。改为按源码/二进制 mtime 比较重建；exe 被运行中进程占用（CS0016）时不算失败，下次启动再编。

## 窗台座位避开标题栏按钮（2026-11-06）

针对「小窗口时坐在右上角，挡住最小化/最大化/关闭」的反馈。原来落点是写死的右上角（`_targetRect.Right - Width - 12 + _padX`）。

新增 `PerchLeft()`，按窗口宽度自适应：

- **够宽 → 仍贴右侧，但让开按钮条**：按钮条宽度取 `SM_CXSIZE × 3`，加余量 10 DIP
- **太窄 → 改坐左上角**：右侧放不下时，标题栏左端只有图标和标题文字，不承载操作
- 判定阈值 ≈ **248 DIP**（按钮 96 + 两边余量 20 + 立绘宽度），按「右侧放不放得下」判断而非窗口大小硬编码

两个实现细节的坑：

- `SM_CXPADDEDBORDER` 在**系统 DPI 感知进程**里读出来是 `0`，但按钮条实际有内边距。直接信任会让估计偏窄、立绘压上去，所以给它加了 8 DIP 下限
- 左上角分支的 `_padX` 符号：Left 是窗口坐标，立绘从 `Left + _padX` 开始，因此左侧落点是 `window.Left + Margin - _padX`

QA 实测（`--qa-fg-file` 驱动真实 `UpdatePerch`，回读宿主真实窗口矩形算重叠；DPI 200%）：

| 1400×800 | 右上 | 724.0 | 738.0 | 0 |
| 1000×700 | 右上 | 526.5 | 538.0 | 0 |

| 700×600 | 右上 | 374.0 | 388.0 | 0 |

另有 52 组几何扫描（窗口偏移 0–900 DIP × 宽 300–1600 DIP）全部无重叠、不出屏。

## 窗台规则修正（2026-11-05，Phase 3 之后）

针对「全屏时还会往屏幕右上角跑」「窗口一动就追」两个反馈，宿主控制器改成两条明确规则：

- **全屏 / 最大化前台 → 右下角趴着**：全屏窗口（覆盖整个显示器）**和最大化窗口**（`IsZoomed`）都不再当作窗台目标。判定为全屏时，她会滑到工作区**右下角**，进入 `peek` 姿态趴着（`ledgeY=975` 对齐底边，只露上半身、手搭在底边上），全屏期间一直保持；全屏期间不散步、不触发探头彩蛋。全屏结束站起来，回到正常趴窗台判定。判定带 1.2s 稳定期，快速 Alt-Tab 不会让她来回跑；从坐姿切到右下角时先起身（不会「坐着滑行」）
- **窗口必须稳定 5 秒才过去**：前台窗口的 hwnd + 真实边界 + 全屏标记连续 5 秒不变，才成为趴台目标。被拖动/缩放/来回切换的窗口不追；已经坐在窗台上时窗口一动，她先起身原地等，窗口停稳 5 秒后再重新过去坐下
- 其余不变：坐姿仍需深度空闲（5s 无交互/无任务）后 1.2s 坐稳；任何交互/任务立刻起身

QA（`--qa-trace` / `--qa-fg-file` 模拟前台窗口，确定性复现）实测：稳定窗口 5.0s 后目标生效 → 移动过去 → 坐下；窗口每 2s 移动一次期间目标始终不生效、她原地不动；切全屏 1.2s 内起身、约 2.5s 滑到右下角、3.4s 进入趴姿并保持；切回普通窗口 5s 后再回到窗口上沿坐下（2026-11-06 起座位改为避开标题栏按钮，见上节）。实机（最大化窗口在前台）截图确认她停在右下角。

### 目光待机回中（2026-11-05）

原来的目光是「死死锁在光标上」：只要鼠标停在那里，她就一直斜眼看着，长时间不动看起来很怪。现在把**看向鼠标**当作对「鼠标在动」的反应：

- 1.5s 内光标有过位移 → 跟随（虹膜快速跟到光标方向，`eyeRate=10`）
- 光标停住超过 1.5s → 目光平滑回到正视前方（`eyeRate=3.5`，约 0.5–0.8s 回中），身体那一点点前倾也跟着复位
- 验证（`--qa-cursor` 钉住光标 + 离屏帧）：跟随态 `gaze=(-0.11,0.61)` → 停 1.5s 后 `gaze=(0,0.03)`；对比图 `docs/images/gaze-idle-return.png`（左：跟随中，右：回中）
